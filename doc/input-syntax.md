# Input-file syntax

A FeenoX input file is a line-oriented plain-text description of a problem. It can contain
definitions, instructions, comments and algebraic expressions. Files normally use the
extension `.fee`.

This chapter spells out the syntax explicitly so that input files can be written by hand or
generated by scripts and other tools without guessing. The generated [reference](feenox-manual.md#reference)
remains the authoritative list for a particular FeenoX version.

## Lexical rules

 * Put one instruction on each logical line. Split a long line either with a trailing
   backslash or by enclosing the continued part in braces:

   ```feenox
   BC loaded-face tx=load(t) \
                  ty=0

   BC loaded-face { tx=load(t)
                    ty=0 }
   ```

 * `#` and `;` start a comment outside quoted strings. A backslash escapes special
   characters.
 * Whitespace separates keyword arguments. Expressions supplied as keyword arguments
   therefore need to be single tokens. Quote the whole token if the expression contains
   spaces:

   ```feenox
   BC loaded-face "tx = load(t + 1)"
   ```

   The quotes group the characters into one argument; they do not turn a valid expression
   into literal text.
 * Top-level instruction keywords such as `PROBLEM`, `MATERIAL`, `BC`, and `WRITE_RESULTS`
   are case-insensitive. Do not rely on that behavior for identifiers, material-property
   names, problem-specific keyword arguments, or boundary-condition keys: use the exact
   spelling shown in the reference.
 * A boundary-condition datum or problem-specific `name=value` property is one token.
   Keep it unquoted if it has no spaces, or quote the whole token if its expression does.

## Expressions and assignments

FeenoX accepts expressions where numbers are expected. User-defined variables and
functions can therefore replace constants in most keywords, properties and boundary
conditions:

```feenox
omega = 2.5
T_wall(t) := 300 + 20*sin(omega*t)
```

The assignment operators have the following meanings:

 * `name = expression` assigns a scalar, vector element or matrix element; if implicit
   declaration is enabled, a previously unknown scalar is declared by the first assignment.
 * `f(x,...) = expression` and `f(x,...) := expression` are equivalent ways to declare
   an algebraic function.
 * `x .= expression` explicitly assigns a DAE equation to a phase-space object.

Do not use `:=` for an ordinary parameter or material property assignment.

Element-wise vector and matrix assignments need subscripts. The special indices `i` and
`j` sweep over the dimensions:

```feenox
VECTOR x SIZE 3
x[i] = i^2

MATRIX A ROWS 2 COLS 2
A[i,j] = 10*i + j
```

An entire vector can alternatively be initialized from a parenthesized list, such as
`x = (1, 4, 9)`. Pointwise-defined and externally stored functions are declared with the
`FUNCTION` keyword and options such as `DATA`, `FILE`, or `VECTORS`; do not use a
parenthesized assignment for those cases.

## Quoting and `PRINT`

Quotes are token delimiters, not a request for literal output. For example:

```feenox
PRINT "1 + 1"
```

prints `2`, because `1 + 1` is parsed as one expression token. To print the expression
verbatim, make the token literal with `TEXT`:

```feenox
PRINT TEXT "1 + 1"
```

prints `1 + 1`. The same rule applies to strings used in other contexts: quote whenever
one token contains spaces, and use the instruction-specific literal marker when literal
interpretation is required.

## Minimal PDE recipe

A typical finite-element input follows this order:

1. Select the problem and read its mesh.
2. Assign material or problem parameters.
3. Declare boundary conditions.
4. Set time stepping and initial conditions, if needed.
5. Request an explicit result or use `WRITE_RESULTS`.

For example, a complete steady thermal input for a mesh whose volume group is
`steel` and whose boundary groups are `left`, `right`, `top`, and `bottom` can be:

```feenox
PROBLEM thermal 2D MESH square.msh

MATERIAL steel k=50

BC left  T=300
BC right h=10 Tref=293
BC top   q=0
BC bottom q=0

WRITE_RESULTS FILE temperature.vtk T
```

The mesh must contain physical groups compatible with the material and boundary
conditions. By default, a `MATERIAL` and a `BC` link to a mesh physical group with the
same name. Use `MATERIAL`/`BC` indirection through `PHYSICAL_GROUP`, or explicit
`GROUP`/`GROUPS` on a `BC`, when the names differ.

## `PROBLEM` and build capabilities

`PROBLEM` selects the equation and activates its problem-specific keywords, properties,
result functions and boundary-condition parser. Put problem-specific instructions after
it.

PDE support requires PETSc. Modal/eigenvalue support additionally requires SLEPc, and
some solver choices require the corresponding PETSc implementation to be installed.
Run `feenox --pdes` to see the PDEs compiled into the executable in use; do not assume
that every problem listed in documentation is available in every binary.

## Boundary-condition syntax

The general form is:

```feenox
BC <name> <bc_data> [<bc_data> ...] [GROUP <mesh_group> ...]
BC <name> <bc_data> [<bc_data> ...] GROUPS <mesh_group> ...
```

If no explicit `GROUP` or `GROUPS` is present, `<name>` is also the mesh physical-group
name. Several data tokens may be needed for one condition:

```feenox
BC coolant h=750 Tref=300
BC loaded  p=1e5
BC support u=0 v=0
```

Each `<bc_data>` uses the keys accepted by the selected `PROBLEM`, not a generic set shared
by all PDEs. The most important difference is case: thermal uses `T`, thermal hydraulics
also has `T`, `T0` and `p0`, mechanical uses `u`, `v`, `w`, while Laplace uses `phi`.
Consult the boundary-condition subsection for that problem.

Use the `if()` functional when a boundary-condition value should vary while the
boundary condition remains active:

```feenox
BC load Fx=if(t<10,1000,0)
```

To activate or deactivate a complete BC datum, put a condition before `=>`:

```feenox
BC load (t<10)=>Fx=1000
BC fixed-end (1-(t<10))=>fixed
```

The datum is active when the absolute value of the condition exceeds FeenoX's small
built-in condition threshold; zero deactivates it. This is distinct from `if()`: a
zero-valued Dirichlet or force expression still defines an active condition.
Keep the complete quoted or unquoted datum as one token.

The expression lexer does not combine `<=` or `>=` into a single comparison operator.
Use strict comparisons and arithmetic or logical combinations instead; the second line
above is a complement of `t<10`.

## Guidance for generated input files

When a script or another tool generates a `.fee` file:

 * start from a known FeenoX example with the same `PROBLEM`;
 * copy physical-group names from the actual mesh, not from a generic example;
 * use the exact units and load sign conventions documented for the selected boundary
   condition;
 * distinguish zero-valued data (`q=0`, `u=0`) from valueless flags (`fixed`, `symmetry`,
   `vacuum`, `adiabatic`);
 * do not invent keywords, aliases, properties or output names—look them up in the generated
   problem-specific reference;
 * preserve `name=value` as one token for `BC`, `JUNCTION`, and similar parsers, quoting
   the whole token when its expression contains spaces;
 * finish by running `feenox --check input.fee ...` and then the smallest representative
   solve.
